Hands-on database learning

Practice SQL by seeing the database change.

The CodeLeaf SQL playground is made for short experiments: define a schema, insert a few rows, query them, and inspect the result. It accepts common MySQL-style syntax while running each practice session in an isolated sandbox.

A useful first exercise

Open the workspace, choose SQL, and run the following as one script or as separate notebook cells:

CREATE TABLE courses (
  course_id INT PRIMARY KEY,
  title VARCHAR(80) NOT NULL,
  credits INT
);

INSERT INTO courses VALUES
  (101, 'Database Systems', 4),
  (102, 'Web Programming', 3);

SELECT title, credits
FROM courses
WHERE credits >= 3
ORDER BY title;

The result should show both courses ordered by title. If you run the CREATE TABLE statement again in the same notebook state, the database correctly reports that the table already exists. Use a new runtime or DROP TABLE when you intentionally want to start over.

Keys and constraints

Use PRIMARY KEY for a row identity, composite keys when uniqueness depends on multiple columns, UNIQUE for alternate identifiers, and FOREIGN KEY for relationships. Constraint errors are feedback about the data model.

Joins and grouping

Practice INNER JOIN, LEFT JOIN, COUNT, SUM, AVG, GROUP BY, and HAVING with two related tables. Qualify column names with aliases when tables share a field such as id.

Notebook workflow

Keep schema setup, seed data, and analysis in separate cells. Run cells in order, read each output below the editor, and use the runtime reset control when you need a clean state.

Common mistakes to learn from

  1. Duplicate primary keys: inserting the same key twice should fail. Do not hide the error with INSERT OR REPLACE unless replacement is your deliberate lesson.
  2. Missing foreign-key parents: insert the referenced department, user, or course before inserting the child row.
  3. Unexpected duplicates after a join: inspect the relationship and join condition. A one-to-many relation can create several result rows for one parent.
  4. Filtering aggregates with WHERE: use WHERE before grouping and HAVING after grouping.
  5. Changing the schema without checking state: a notebook remembers successful mutations between cell runs. Reset the runtime when repeating a setup exercise.

What the sandbox is for

This playground is intended for education, interview preparation, and classroom exercises. It is bounded for safety and convenience, so it should not be treated as a hosted MySQL production database. Use small practice datasets, never paste passwords or private customer data, and validate important queries in the actual database engine you will use.
